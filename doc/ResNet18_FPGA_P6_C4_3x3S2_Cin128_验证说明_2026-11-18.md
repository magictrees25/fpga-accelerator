| 项目 | 完整代表层 | 本地硬件任务 |
|---|---|---|
| 输入 | 28×28×128 | 9×9×128，包含所需 halo |
| 卷积核 | 3×3 | 3×3 |

| padding | 1 | 0，边界零由 Host 装载 |
| 输出 | 14×14×256 | 4×4×8 |

| C-Tile | 两组，每组 64 通道 | 每组 K=3×3×64=576 |

新顶层 `fpga_system_top_p6_3x3s2_c128_tile` 沿用已通过的 Cin128 两段调度 FSM：每个 M 先计算 C0，再计算 C1，只在 C1 完成后写回一次。

最小适配如下：

1. 激活 Reader 使用已有 `conv_bram_reader_p4_3x3s2` 的外部共享 BRAM 模式。
2. K Controller 和 Weight Reader 的 `k_len` 均设为 576。
3. 本地激活地址合法范围改为 9×9×64=5184 字节，权重地址为 0～575。
4. 保留已有 P2 PE、MAC、K Controller、共享激活/权重 BRAM 和输出 BRAM。

每段 288 个双 K FEED；C0 清累加器，C1 仅清流水线并继续累加。每段完成后的 13 拍 DRAIN 沿用原核心配置。K Controller 的全局 K 偏移模式保持关闭。

## 关键：C 分块不等于直接切开标准展平的 K

每个 C-Tile 都必须遍历全部九个卷积核位置：

```text
local_k = (ky*3+kx)*64 + local_c          // 0..575
global_c = load_c_tile*64 + local_c      // 0..127
weight_word_addr = local_k
weight_lane[n] = kernel[ky][kx][global_c][output_channel_base+n]
```

标准 `ky/kx/Cin128` 展平顺序下，对应的 K 地址为：

```text
standard_k = (local_k/64)*128 + load_c_tile*64 + local_k%64
```

不能用 `load_c_tile*576+local_k` 代替上述通道映射。C0 计算九个位置的通道 0～63，C1 计算九个位置的通道 64～127；两个部分和相加得到完整卷积。

## Host 装载协议与激活地址

端口沿用 Cin128 顶层接口，`load_c_tile` 为 1 位。每次 `load_req` 提供当前 M 和 C-Tile：

```text
local_output_y = M/4
local_output_x = M%4
local_input_y = 2*local_output_y + ky
local_input_x = 2*local_output_x + kx
activation_byte_addr = (local_input_y*9+local_input_x)*64+local_c

global_input_y = 2*(output_origin_y+local_output_y)+ky-1
global_input_x = 2*(output_origin_x+local_output_x)+kx-1
```

TB 只装载当前 M 所需的 3×3×64=576 个激活字节，写入本地 9×9 HWC 布局中的对应位置；随后装载 576 个 64-bit 权重字。其余激活位置不会读取，无需初始化。

越出完整 28×28 图像的坐标写入零。`busy` 在装载期间保持高；完成所有写入并撤销写使能后，才发送单拍 `load_done`。下一组通道覆盖写回同一批本地地址，等待期间 PE 部分和保持。

当前权重和激活按 M 重复装载，用于功能验证，尚未进行跨 M 数据复用优化。

## Golden 与检查范围

独立 Golden 使用 oy、ox、n、ky、kx、c 六重循环，从完整 28×28×128 输入直接计算标准卷积，并按全局坐标判断补零。不调用 DUT、局部 K 解码、BRAM 地址或装载辅助函数。

Golden 另外统计补零项数量，逐项结果与 TB 读回比较；逐段的 PE 参考用于核对部分和，两段最终结果必须与六重循环 Golden 一致。

TB 检查：

- 每次装载请求与确认、M/C 元数据、576 个激活和权重写入的地址、内容及 Bank。
- 每段实际请求/FEED 的局部 K=0、2、…、574，两路激活和八路权重的配对、符号和响应时序。
- K=64/128 等卷积核位置切换、K=192/384 卷积核行切换；每段分别覆盖八次和两次切换。
- C1 装载等待期间全部 64 个 PE 部分和保持；C0 清累加器，C1 继续累加。
- 每段完成后核对八个累计结果快照与 64 个 PE 累加器。
- 仅 C1 完成后写回，地址 0～15 各一次，mask 全有效。
- 同步 32-bit lane 读回按置换顺序执行，在采样时钟沿后等待 `#1` 比较。
- 三轮连续启动、两次权重组切换、旧输出覆盖、384/384 结果和读回。
- 补零装载与 FEED 数量、请求等待/完成等待的 2000 拍上限，以及 1000000 拍全局 watchdog。

等待上限已按 K=576 调整，覆盖 288 拍 FEED、DRAIN 及控制开销。
