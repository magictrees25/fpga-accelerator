## 目标与 RTL 改动

目标层为 `layer4.0.conv1`：输入 14×14×256，3×3、stride=2、padding=1，输出 7×7×512。

硬件一次仍计算固定 4×4×8 输出 Tile，M=16、N=8。完整 K=3×3×256=2304，按四组输入通道分块，每段 K=576。

| C-Tile | 输入通道 | 清累加器 | 段完成后的动作 |
|---:|---|---|---|
| C0 | 0～63 | 是 | 请求 C1 数据 |
| C1 | 64～127 | 否 | 请求 C2 数据 |
| C2 | 128～191 | 否 | 请求 C3 数据 |
| C3 | 192～255 | 否 | 写回最终结果 |

相对已通过的 Cin128 3×3 顶层，仅将 `load_c_tile` 与内部 `c_tile_idx` 扩为 2 位，调整四段循环、首段清累加器条件和最终写回条件。每个 M 完成后从 C0 开始下一 M；连续任务也从 C0 开始。

PE、MAC、Reader、K Controller 不变，仍使用两路 K 数据，每段 288 个 FEED 周期和 13 拍 DRAIN。两处 `k_len` 均保持 576，本地 BRAM 容量不扩大。

## 通道映射与装载协议

每个 C-Tile 遍历全部九个卷积核位置：

```text
local_k = (ky*3+kx)*64 + local_c                  // 0..575
global_c = load_c_tile*64 + local_c              // 0..255
standard_k = (local_k/64)*256 + load_c_tile*64 + local_k%64
```

标准 `ky/kx/Cin256` 展平地址不能用 `load_c_tile*576+local_k` 代替。

每次 `load_req` 等待 Host 装载当前 M/C 所需的 576 个激活字节和 576 个权重字：

```text
activation_byte_addr = ((2*(M/4)+ky)*9 + 2*(M%4)+kx)*64 + local_c
weight_word_addr = local_k
weight_lane[n] = kernel[ky][kx][global_c][output_channel_base+n]

global_input_y = 2*(output_origin_y+M/4)+ky-1
global_input_x = 2*(output_origin_x+M%4)+kx-1
```

本地输入布局为 9×9×64，地址范围 0～5183。分组覆盖写入同一批地址；K Controller 的全局偏移模式保持关闭。`busy` 在等待期间为高，撤销写使能后才脉冲 `load_done`。每个 M 当前所需窗口外的激活位置无需初始化。

## 局部测试

一个 DUT、一次复位，固定一份完整输入与权重，连续运行三个完整 4×4×8 Tile：

| job | 全局输出起点 | 输出通道 | 目的 |
|---:|---|---|---|
| 0 | (1,1) | 24～31 | 内部位置、四段 K=576 |
| 1 | (0,0) | 0～7 | 左上 padding=1 |
| 2 | (3,3) | 504～511 | 右下边界和最后通道组 |

左上用例预期 5888 个补零装载字节、2944 个补零 FEED 对；另外两个用例没有补零。最后有效输出坐标 6 读取输入 11～13，不应额外补底部/右侧零。

局部 Golden 使用 oy、ox、n、ky、kx、c 六重循环，直接索引完整输入并处理 padding，不使用 DUT 或本地装载/地址辅助函数。独立软件计算确认三个用例的四段贡献及前三段累计值均非零；后两轮各有 128 个输出值变化。

## 整层测试

按空间 Tile 行、列及输出通道组遍历，共 ceil(7/4)×ceil(7/4)×(512/8)=2×2×64=256 个逻辑 Tile。

| Tile 空间有效范围 | Tile 数（含通道组） | 每 Tile 有效结果 | 每 Tile 物理结果 |
|---|---:|---:|---:|
| 4×4 | 64 | 128 | 128 |
| 4×3 / 3×4 | 128 | 96 | 128 |
| 3×3 | 64 | 72 | 128 |
| 合计 | 256 | 25088 | 32768 |

完整六重循环 Golden 在任何 start 前计算。全部 Tile 使用同一份完整图像与权重。实际同步读回值拼接到全局 HWC 输出，最终逐项核对 25088 个结果、覆盖次数及来源 Tile。

区分两类置零：

- 有效输出的卷积 padding：全局输出在 0～6 内，仅超出输入 0～13 的 tap 置零。预期 671744 个装载字节、335872 个 FEED 对。
- 无效输出的空间尾部：输出坐标 7 不属于网络结果，整个 3×3×256 窗口全部置零。预期 2211840 个装载字节、1105920 个 FEED 对；7680 个物理结果应为零，不得拼入全局数组。

特别注意：无效输出 y=7 的 ky=0 仍对应输入 y=13，因此不能仅判断输入坐标越界。TB 会先判断输出是否属于空间尾部，再决定是否允许读取图像。

## 核心检查与预期计数

两套 TB 均保留实际写接口、逐拍请求/响应和数据配对检查，不直接修改内部 BRAM，不使用 `force`。新增或扩展检查包括：

- 四组通道编号与局部 K、卷积核位置/行切换正确。
- 每段结束后核对八个累计输出快照及全部 64 个 PE 累加器。
- C1/C2/C3 装载等待期间保持前一段累计部分和，清流水线不能误清累加器。
- 只有第四段完成后才写回一次；地址、mask 和计数正确。
- 连续 start/done、权重组切换、旧缓存覆盖、同步 32-bit lane 读回正确。
- 独立 padding 计数、整层空间尾部排除、全局位置唯一写入。
- 请求/完成等待超时 2000 拍；局部全局 watchdog 1000000 拍，整层 60000000 拍。未完成不得 PASS。
