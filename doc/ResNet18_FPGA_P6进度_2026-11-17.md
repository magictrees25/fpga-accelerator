## 1. 项目目标与开发原则

项目目标是完成面向图像分类的 ResNet-18 FPGA 卷积加速器设计与验证。当前主线以自研 RTL 卷积计算核心为重点，采用 INT8 数据通路和 8×8 systolic PE 阵列，并逐步完善 K/M/N 分块控制、BRAM 数据读取、跨 K-Tile 累加及整层卷积映射。

当前开发不是重新规划课题，而是在已有 P5 工程基础上逐阶段增强和验证。

### 1.1 已确定的硬件基线

- PE 阵列：8×8，共 64 个 PE。
- Activation：有符号 INT8（具体输入打包和 Reader 数据组织以现有 RTL 为准）。
- Weight：有符号 INT8。
- Product：INT16。
- Partial sum / accumulator：INT32。
- MAC：三级流水，输入寄存、乘法寄存、累加。
- 阵列输出：每列汇总 8 行 PE 的 INT32 部分和，形成 8 路输出。
- K 维按 Tile 分段处理；Tile 之间需要清理流水线，但不能错误清除此前累加的 INT32 部分和。

### 1.2 开发习惯与约束

1. 以当前 Git 分支代码为准，不凭旧截图或旧版本猜测接口。
2. 一次优先修改一个 RTL 模块，配套独立 Testbench 验证。
3. 已通过的 P5、P6-A、P6-B1 测试文件保留，不覆盖、不随意删除。
4. 修改 RTL 前先检查模块完整代码、端口、参数及所有实例化位置。
5. 不把“编译通过”当成“功能通过”；必须查看 XSim Transcript / Golden 比对结果。
6. 未经实际仿真，不提前宣称 PASS。
8. 当前 P6-B2-3 的问题尚未修复，不要继续修改 GEMM Controller 或其他模块。

## 3. P6-A：跨 K-Tile INT32 部分和累加验证（已完成）

### 3.1 目标

验证同一个输出在 K 维分成多个 Tile 计算时：

- 第一个 K-Tile 清空 INT32 累加器；
- 后续 K-Tile 只清理流水线；
- 后续 Tile 必须保留之前 Tile 的 INT32 部分和；
- 最终累加结果与独立 Golden 模型一致。

### 3.2 RTL 修改

P6-A 对以下模块进行了配套修改：

#### `rtl/mac_unit.sv`

将清除控制拆分为两个独立信号：

- `clear_acc`：清除 INT32 accumulator 和 overflow flag。
- `clear_pipe`：清除输入寄存器和乘法流水寄存器，但保留 INT32 accumulator 和 overflow flag。

累加器控制优先级为：

`Reset > clear_acc > clear_pipe > enable`

#### `rtl/systolic_array_p2.sv`

新增并连接 `clear_pipe`：

- 清除 MAC pipeline；
- 清除 weight skew pipeline；
- 清除 valid tracking；
- 不通过 `clear_pipe` 清除 PE INT32 累加器。

#### `rtl/k_tile_controller_p2.sv`

增加/完善独立的 `clear_acc` 和 `clear_pipe` 控制：

- 每次进入清理阶段都清理流水线；
- 是否清理累加器由 `clear_acc_on_start` 决定；
- `valid_reset` 跟随流水线清理。

#### `rtl/gemm_mn_controller_mem_p2.sv`

连接新的清除控制，并在新 M/N 输出 Tile 开始时清空累加器。该阶段仍是当前工程的既有控制结构，尚未实现完整的外层多 K-Tile 自动调度。

### 3.3 P6-A 独立 Testbench

文件：

`tb/tb_p6a_cross_ktile_accum.sv`

测试配置：

- M=1
- N=8
- K_TOTAL=128
- K-Tile 数量=2
- 每个 K-Tile 的 K=64

验证结果：

- 两个 K-Tile 均完成；
- Reader 请求、FEED、DRAIN 计数通过；
- 64 个 PE 的 INT32 累加值与 Golden 一致；
- 8 路 INT32 输出与 Golden 一致；
- Tile 1 执行 `clear_pipe=1`、`clear_acc=0` 后，Tile 0 的部分和保留；
- signed INT8 正负数参与测试；
- 最终仿真 PASS。

P6-A 已提交 Git。之前记录的提交短 SHA 为 `b1151de`；如需核实完整提交和当前 HEAD，应在本地执行 `git log`。

## 6. 当前阶段：P6-B2-3（尚未通过，接口不匹配待修复）

### 6.1 本阶段目标

修改 `k_tile_controller_p2.sv`，使控制器同时保留：

- **局部 K 地址**：用于 PE 阵列内部的数据映射、FEED 调度和局部计数；
- **全局 K 地址**：用于 Activation / Weight BRAM Reader 的请求地址。

目标关系：

\[
K_{\text{global}}=K_{\text{tile\_base}}+K_{\text{local}}
\]

例如 K-Tile 大小为 64：

| Tile | `k_tile_base` | 局部 K-pair 首地址 | 全局 Reader 首地址 | 全局末地址 |
|---|---:|---:|---:|---:|
| 0 | 0 | 0 | 0 | 62 |
| 1 | 64 | 0 | 64 | 126 |
| 2 | 128 | 0 | 128 | 190 |
| ... | ... | ... | ... | ... |
| 8 | 512 | 0 | 512 | 574 |

**重要：不能简单把原有 `k_idx` 改成全局地址。** 局部 K 仍然需要从 0 开始，以保持原有 PE 行映射和 K-Tile 内部计算时序。

### P6-B2-4：GEMM Controller 外层 K-Tile 自动调度

当前 `gemm_mn_controller_mem_p2.sv` 的既有行为是一次 K Controller 计算完成后进入写回流程，尚未实现一个 M/N 输出 Tile 内自动连续执行多个 K-Tile。

计划增加外层 K-Tile 调度：

```text
G_START_K
    |
    v
G_WAIT_K
    |
    v
判断是否还有 K-Tile
    | 有
    +------> 设置下一个 k_tile_base
    |        clear_acc_on_start = 0
    |        启动下一 K-Tile
    |
    | 无
    v
G_WRITE
```

控制原则：

- 第一个 K-Tile：`clear_acc_on_start = 1`；
- 后续 K-Tile：`clear_acc_on_start = 0`；
- 每个 K-Tile 都需要清理流水线；
- 只有最后一个 K-Tile 完成后才允许写回最终输出；
- 仍需处理 M/N Tile 切换时的累加器清零。

先检查当前 GEMM Controller 的 FSM、K Controller 启动握手、写回接口和所有实例化，再修改。不要提前假定状态名和接口。
