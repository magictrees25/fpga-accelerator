## 联合数据通路

```text
TB preload -> conv_activation_bram_shared_p5 -> conv_bram_reader_p4_3x3s2
                                                       |
TB preload -> conv_weight_bram_reader_p5_shared ---------+
                                                       v
                                      gemm_mn_controller_mem_p2
                                      K_TILE_SIZE=64
                                      [K Controller + P2 PE array]
                                                       |
                                                final write only
                                                       v
                                                  output_bram
                                                       |
                                            TB synchronous readback
```

实例都来自当前工程 RTL。Activation/Weight 返回数据由真实 RTL 存储模块提供，没有用 Reader 数据模型替代，没有 `force`，没有直接写入 BRAM 内部数组。TB 仅通过正式 preload 接口装载数据，并向 GEMM 发一次外部 start；内部 K 启动和偏移均由 GEMM 自动产生。

“真实 BRAM”指工程中可综合的同步 BRAM RTL 模块参与行为仿真，不表示已经上板或完成原语级/时序仿真。

## 卷积配置与地址单位

局部输入 `9×9×64`，卷积 `3×3`、stride=2、局部 padding=0，输出 `4×4×8`：

- M=16、N=8、完整 K=576。
- 每个 M 自动执行九个 K=64 的分段。
- 局部 K 用于 PE 行映射，全局 K 用于 Reader 请求。
- Activation preload 使用 HWC **字节地址**，共 5184 字节。
- Shared Activation BRAM 读接口使用 **双字节 Bank 地址**，实际访问范围 0～2591；6400-byte 容量沿用 P5。
- Weight preload 使用完整 K 字地址 0～575，每字是八个 INT8 权重；偶/奇 Bank 读地址均为全局 K/2，范围 0～287。
- **Weight Reader 的 `k_len` 固定接 576，不能连接内部 K Controller 的段长度 64。**
- Output BRAM 深度 16，每字 256 bit，八个 INT32 通道，mask 为 `8'hff`。

本次不验证全局图像 padding、N>8、Cin>64 的重新装载或完整卷积层调度。将当前 K=576 分成九段并不等同于完成 Cin 扩展。

## 两轮连续测试

一个 DUT，只复位一次。两轮均完整装载激活和权重，随后启动计算、等待 done 并读取输出。第二轮使用不同的有符号 INT8 数据，包含 -128 和 127；两个独立软件参考结果显示全部 128 个输出都会改变，用于识别旧缓存内容。

下表是**预期计数，不是已运行结果**：

| 检查项 | 每轮 | 两轮合计 |
|---|---:|---:|
| Activation preload 字节 | 5184 | 10368 |
| Weight preload 64-bit 字 | 576 | 1152 |
| 外部 start/done | 1 | 2 |
| 内部 K start/done | 144 | 288 |
| K-pair 请求/FEED | 4608 | 9216 |
| Activation 返回 | 4608 | 9216 |
| Weight 返回 | 4608 | 9216 |
| DRAIN 周期 | 1872 | 3744 |
| 流水线清理 | 144 | 288 |
| 累加器清零 | 16 | 32 |
| 最终输出写入 | 16 | 32 |
| INT32 输出比较 | 128 | 256 |
| INT32 BRAM 读回比较 | 128 | 256 |

检查覆盖：

- 实际 preload 写入次数、地址、数据打包、偶奇 Bank 写使能。
- 每一组 Reader 请求的完整 K、激活 Bank 地址和权重 Bank 地址。
- 同步 BRAM/Reader 一拍响应延迟、返回标签、激活和权重与 FEED 对齐。
- 自动执行所有 K 段，无人工内部启动；每个 M 从 K=0 重新开始。
- 每段结束后的八个部分和快照及全部 64 个 PE 累加器。
- 清流水线时保留前段部分和，切换 M 时清零累加器。
- 中间 K 段不写回，最终输出地址 0～15 各一次，mask 全有效。
- 最终 Golden 用 `oy/ox/n/ky/kx/c` 六重循环直接计算标准卷积，不使用 DUT 地址或部分和作为参考。
- Output BRAM 每次在地址设置后的有效时钟沿再延迟 `#1` 比较，避免同步读竞争；按置换顺序覆盖全部 16 个地址，逐 lane 检查全部 INT32 数据。
- 第二轮 128 个已改变的输出覆盖旧缓存；全程无复位。
- busy 连续性、单拍 done、启动配置锁存、读写互斥和超时保护。
