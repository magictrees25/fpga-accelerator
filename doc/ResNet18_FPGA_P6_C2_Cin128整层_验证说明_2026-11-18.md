## 参数与调度

| 项目 | 数值 |
|---|---|
| 目标层 | ResNet18 `layer3.0.downsample.0` |
| 输入 | 28×28×128，HWC，INT8 |
| 卷积 | 1×1，stride=2，padding=0 |
| 输出 | 14×14×256，INT32 |
| 单个硬件 Tile | 固定 4×4×8，M=16，N=8，完整 K=128 |
| 通道分块 | C0=0～63，C1=64～127，每段局部 K=64 |
| 数据供给 | 每拍两个 K 元素，沿用现有 P2 核心 |
| 逻辑 Tile 数 | ceil(14/4)×ceil(14/4)×(256/8)=4×4×32=512 |

TB 依次遍历空间 Tile 行、空间 Tile 列、输出通道组：

```text
for ty = 0..3
  for tx = 0..3
    for ng = 0..31
      output_origin = (4*ty, 4*tx)
      output_channels = 8*ng .. 8*ng+7
      start -> 服务 32 次 load_req -> done -> 同步读回 128 个值 -> 全局拼接
```

全部运行只复位一次。每个 Tile 内，对 M0～M15 依次装载 C0、计算并保留部分和、装载 C1、继续累加，之后写一次最终结果。下一 Tile 覆盖同一组本地激活/权重和 Output BRAM。

`load_req` 期间 `busy` 保持高。TB 沿用已通过版本的写入顺序和可变 Host 等待时间；撤销写使能后再脉冲 `load_done`。不直接修改内部存储器，不使用 `force`。

## 空间尾 Tile 的处理

14×14 输出最后一行/列 Tile 起点是 12，其空间有效范围只有 2 行/列。

| Tile 类别 | 含输出通道组的 Tile 数 | 每 Tile 有效结果 | 每 Tile 物理结果 |
|---|---:|---:|---:|
| 内部 4×4×8 | 288 | 128 | 128 |
| 右侧或底部 4×2×8 / 2×4×8 | 192 | 64 | 128 |
| 右下角 2×2×8 | 32 | 32 | 128 |
| 合计 | 512 | 50176 | 65536 |

不修改固定 M=16 的 RTL。TB 在装载前检查全局输出坐标：

- 有效位置从完整输入的 `(2*global_y, 2*global_x, global_c)` 取得数据。
- 超出 14×14 的位置装载零，避免越界访问输入数组；这类位置仍完成两段计算、写回和同步读回，并要求结果为零。
- 仅有效位置拼接到 14×14×256 的全局 HWC 数组。15360 个空间尾部结果不得写入该数组。

**这是固定硬件 Tile 的空间尾部处理，目标卷积仍是 padding=0。** 输出 BRAM 的 mask 仍为 `8'hff`，表示每个物理结果字的八个输出通道有效；它不承担全局空间裁剪功能。

## Golden Model 与拼接检查

完整输入和权重只初始化一次，全部 Tile 使用同一份数据，沿用 P6-C1 的有符号数据公式并固定 `job=0`。

Golden 在启动 DUT 前，通过 y、x、输出通道、输入通道四重循环直接计算：

```text
golden[y][x][n] = sum(c=0..127, image[2*y][2*x][c] * kernel[c][n])
```

完整 Golden 不调用 DUT、BRAM 地址函数或 Tile 装载函数。每 Tile 的局部参考值取自该完整结果；空间尾部期望为零。用于观察 PE 部分和的第二套参考仍逐个通道累加，并与完整 Golden 核对。

输出按置换顺序读回，地址/lane 在时钟沿采样后等待 `#1` 比较。全局拼接的数据来源是实际 `out_rd_data`，不是 Golden 或写回快照。检查包括：

1. 全部 65536 个物理 INT32 写回值和同步读回值正确。
2. 每个有效 HWC 位置恰好写入一次，无重复、遗漏或越界。
3. 每个位置记录来源 Tile；结束时按全局坐标反查应属 Tile，再比较全部 50176 个结果。
4. 全部右边、底边及右下角 Tile 覆盖；15360 个无效空间 lane 为零且不拼入全局。
5. 511 次输出通道组切换，每次权重确实不同；每拍实际 Reader 返回都核对当前全局通道的权重。
6. 每次通道装载的地址、数量、字节/权重打包、Bank 和握手正确。
7. C1 装载等待时 64 个 PE 部分和保持；每段清流水线，只有 C0 清累加器；只有 C1 完成后最终写回。
8. 连续 start/done、每段请求/FEED/DRAIN、每个输出地址与 mask、每次旧缓存覆盖。
9. 单次装载请求/完成等待的超时及 10000000 拍全局 watchdog；未完成不得 PASS。

空间尾部的零值可能与上一 Tile 相同，因此缓存覆盖不强制每轮 128 个值都变化；TB 独立计算本轮应变化的数量，并逐项验证。独立软件计算预期总计 **50304 个变化后的缓存结果**。
