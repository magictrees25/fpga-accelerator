## 为什么新增独立顶层

P6-B2-4 的 GEMM 调度使用全局 K 地址，要求待计算数据已在 BRAM 中；它没有等待 Host 重新装载下一组通道的接口。现有 64 个 PE 的累加器也只保存当前一个 M/N 输出组的部分和。

因此本轮新增 `rtl/fpga_system_top_p6_1x1_c128_tile.sv`，用一个小型调度状态机完成以下顺序：

```text
外部 start
  -> M0/C0 装载等待 -> K=64 计算，清累加器
  -> M0/C1 装载等待 -> K=64 计算，保留部分和
  -> M0 最终写回
  -> M1/C0 装载等待 -> ...
  -> M15/C1 计算 -> 最终写回 -> done
```

顶层直接例化已经通过验证的 K Controller、P2 PE、P4 1×1 Reader、共享激活/权重 BRAM 和 Output BRAM。原 GEMM Controller 及 P5/P6 顶层均不修改。

每次装载只写当前 M 需要的 64 个激活，权重为 64 个 64-bit 字。其他激活位置不需要初始化，也不会访问。权重随 M 重复装载，是此阶段的功能实现选择；本轮不声称完成权重复用、最佳带宽或高效整层调度。

## 目标网络与局部参数

目标代表层为 `layer3.0.downsample.0`：

- 完整参考输入：28×28×128。
- 卷积：1×1，stride=2，padding=0。
- 完整参考输出：14×14×256。
- 本硬件一次输出 Tile：4×4×8，M=16、N=8、完整 K=128。
- C0：输入通道 0～63；C1：输入通道 64～127。
- 每段使用局部 K=64，8×8 PE 不变，每拍两个 K 元素。

TB 验证两个局部 Tile：

| job | 全局输出起点 (y,x) | 输出通道组 | 完整 Cin |
|---|---|---|---:|
| 0 | (0,0) | 0～7 | 128 |
| 1 | (8,4) | 248～255 | 128 |

同一 DUT，中间无复位；第二轮改变数据。空间起点和全局输出通道选择由 TB/Host 负责，新顶层只处理固定的本地 M=16、N=8。本轮没有自动调度全部 N 组，也未验证整层 50176 个输出或 14×14 空间尾 Tile。

## Host 装载接口

新顶层新增握手信号：

| 信号 | 方向 | 含义 |
|---|---|---|
| `load_req` | 输出 | 需要 Host 装载；保持高直到收到 `load_done` |
| `load_m_addr[3:0]` | 输出 | 当前局部输出 M=0～15 |
| `load_c_tile` | 输出 | 0 对应 C0，1 对应 C1 |
| `load_done` | 输入 | 装载完成确认，一拍；不能与写使能同拍 |

协议：

1. Host 发一次 `start`，顶层进入装载等待。
2. `load_req=1` 时按请求的 M/C 元数据写入所需激活和权重。
3. 所有数据写入完成后撤销写使能，再脉冲 `load_done`。
4. 顶层撤销 `load_req`，启动计算；第一段完成后请求第二段。
5. 两段完成后只写一次最终结果；最终 M 完成后产生单拍 `done`。

**`busy` 在装载等待期间仍为高。Host 是否可以写入由 `load_req` 判断，不是由 `!busy` 判断。** `load_done` 是 Host 的就绪承诺，硬件不自行核实写入总数；TB 会逐笔核对。

BRAM 地址仍是原 64 通道局部布局：

```text
oy = M / 4
ox = M % 4
activation_byte_addr = ((2*oy)*8 + 2*ox)*64 + c_local
weight_word_addr = c_local                         // 0..63
global_c = load_c_tile*64 + c_local
```

每个权重字的 lane n 存储 `kernel[global_c][global_output_channel_base+n]`。激活来自完整参考图像的：

```text
global_input_y = 2*(global_output_origin_y + oy)
global_input_x = 2*(global_output_origin_x + ox)
```

此处已经把后一组通道重新写入局部 BRAM，因此 K Controller 使用 `USE_K_TILE_BASE=0`，Reader 的 K 地址始终为 0～63。不能把全局通道 64～127 直接当作这次局部 Reader 地址。

Output BRAM 沿用同步 32-bit lane 读回封装。地址 0～15，lane 0～7；地址和 lane 在读时钟沿被采样，TB 在该沿后 `#1` 再比较。

## 预期计数与检查

下列为预期值，尚未运行验证：

| 项目 | 每轮 | 两轮 |
|---|---:|---:|
| Host 装载请求/确认 | 32 | 64 |
| K start/done | 32 | 64 |
| 激活装载字节 | 2048 | 4096 |
| 权重装载 64-bit 字 | 2048 | 4096 |
| 请求/FEED K-pair | 1024 | 2048 |
| DRAIN 周期 | 416 | 832 |
| 清流水线 | 32 | 64 |
| 清累加器 | 16 | 32 |
| 最终结果写入 | 16 | 32 |
| INT32 结果/读回 | 各 128 | 各 256 |

TB 检查：

- 请求元数据稳定，Host 加入可变延迟时，计算暂停且 busy 保持。
- 通过正式写接口装载数据，无直接修改内部 BRAM 或 `force`。
- 逐笔检查实际写入计数、激活地址、权重字打包和偶奇 Bank。
- C1 装载等待期间逐周期检查 64 个 PE 部分和不变。
- 首段清累加器，第二段仅清流水线，M 切换后重新清累加器。
- 每一拍 Reader 请求/返回、局部 K、全局输入通道及 PE 激活行对齐。
- 两段各 32 个 K-pair 和 13 拍 DRAIN；每段末尾逐项检查部分和。
- 只有第二段完成后才写回；每个 M 地址恰好写一次。
- 独立 Golden 从完整 28×28×128 输入直接计算 1×1/S2 卷积，逐项累加全部 128 通道。
- 全部 32-bit lane 按置换顺序同步读回；第二轮全部 128 个变化后的值覆盖旧结果。
- 每次等待的超时机制及全局 watchdog。
