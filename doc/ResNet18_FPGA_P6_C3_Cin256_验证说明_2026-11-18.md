## 目标与最小 RTL 适配

目标代表层 `layer4.0.downsample.0`：输入 14×14×256，1×1、stride=2、padding=0，输出 7×7×512。

每次硬件任务仍输出固定 4×4×8，M=16、N=8，但完整 K 从 128 扩为 256。继续复用已有 P2 的 8×8 PE、K Controller、1×1 Reader、共享激活/权重 BRAM 和同步输出 BRAM。

新增顶层：`fpga_system_top_p6_1x1_c256_tile`。相对已通过的 Cin128 顶层，关键改动如下：

1. `load_c_tile` 和内部 `c_tile_idx` 从 1 位扩为 2 位。
2. 每个 M 按 C0→C1→C2→C3 顺序执行四次装载与 K=64 计算。
3. `clear_acc_on_start = (c_tile_idx == 0)`，只有 C0 清累加器；每段均清流水线。
4. C0、C1、C2 完成后返回装载等待；只有 C3 完成后进入最终写回。
5. 写回断言要求 `c_tile_idx == 3`，下一 M 或新的任务重新从 C0 开始。

| load_c_tile | 全局输入通道 | 清累加器 | 完成后 |
|---:|---|---|---|
| 0 | 0～63 | 是 | 等待 C1 装载 |
| 1 | 64～127 | 否 | 等待 C2 装载 |
| 2 | 128～191 | 否 | 等待 C3 装载 |
| 3 | 192～255 | 否 | 写一次最终 INT32 结果 |

不扩大本地 BRAM 容量，不修改原 PE、MAC、Reader 或 K Controller。

## Host 装载与地址

`busy` 在装载等待期间保持高。Host 应等待 `load_req`，根据 `load_m_addr` 和 **2 位** `load_c_tile` 写入当前 M 所需的 64 个激活字节和 64 个权重字；撤销写使能后再发送单拍 `load_done`。

```text
local_y = M / 4
local_x = M % 4
activation_byte_addr = ((2*local_y)*8 + 2*local_x)*64 + local_c
weight_word_addr = local_c                      // 0..63
global_c = 64*load_c_tile + local_c              // 0..255
global_input_y = 2*(output_origin_y + local_y)
global_input_x = 2*(output_origin_x + local_x)
```

每个权重字包含 `kernel[global_c][output_channel_base + lane]` 的八个 INT8 值。

通道组数据覆盖写入同一组本地地址。因此 Reader 和 K Controller 仍使用局部 K=0～63，`USE_K_TILE_BASE=0`，不能把全局通道偏移直接传给本地 Reader。

## 两级验证

两个仿真入口复用 `tb_p6_1x1_c256_common.sv`，每次运行都只例化一个 DUT，避免两套检查逻辑不一致。请先运行局部测试，通过后再运行整层。

### 第一项：局部 Tile 连续两轮

Simulation Top：`tb_fpga_system_top_p6_1x1_c256_tile`。

| job | 全局输出起点 | 输出通道 | 有效输出 |
|---:|---|---|---:|
| 0 | (0,0) | 0～7 | 128 |
| 1 | (2,2) | 504～511 | 128 |

两轮均为完整 4×4×8 Tile，中间无复位；第二轮改变空间位置和输出通道组。全部输入和权重来自同一份完整参考数据。软件参考确认第二轮 128 个结果均不同于上一轮缓存值，且四段贡献及前三段累积值都非零，能观察漏段、误清零和旧缓存问题。

### 第二项：整层连续计算

Simulation Top：`tb_fpga_system_top_p6_1x1_c256_full_layer`。

按空间行、空间列、输出通道组遍历：2×2×64=256 个逻辑 Tile。全局输出使用 HWC 顺序。

| 空间类别 | 含通道组的 Tile 数 | 每 Tile 有效输出 | 每 Tile 物理输出 |
|---|---:|---:|---:|
| 4×4 | 64 | 128 | 128 |
| 4×3 / 3×4 | 128 | 96 | 128 |
| 3×3 | 64 | 72 | 128 |
| 合计 | 256 | 25088 | 32768 |

边缘 Tile 起点为 4，只剩 3 行/列有效位置。越界的 M 装载零并完成计算、写回和读回，要求结果为零，但不拼入 7×7×512 输出数组。这是固定 Tile 的空间尾部处理，目标卷积仍为 padding=0。

## 检查范围与独立 Golden

TB 在任何任务启动前初始化一次完整输入和权重，并以四重循环直接计算：

```text
for y = 0..6
  for x = 0..6
    for n = 0..511
      sum = 0
      for c = 0..255
        sum += image[2*y][2*x][c] * kernel[c][n]
```

使用有符号 INT8 激励与 INT32 结果，Golden 不调用 DUT、局部 BRAM 地址或 Tile 装载函数。逐段 PE 参考另外按每段 64 通道累计，并核对最终结果等于完整 Golden。

保留已通过 TB 的逐拍检查并扩展至四段：

- 四段装载元数据、每笔激活/权重写地址、打包顺序、Bank、64 项装载数量和就绪握手。
- 每段的 32 个双 K 请求/FEED，局部 K、全局输入通道、Reader 响应延迟、激活和权重对齐。
- 每段 13 拍 DRAIN、一次流水线清零；每 M 只有一次累加器清零。
- 每段完成时检查八个累计快照与全部 64 个 PE 部分和。
- C1、C2、C3 的可变 Host 装载等待期间，所有 PE 累积值等于前一段结果并保持不变。
- 中间段不得写回；四段全部完成后每个 M 仅写一次，地址 0～15，mask=`8'hff`。
- 同步 BRAM 读地址/lane 在时钟沿被采样后等待 `#1`，按置换顺序读回全部 128 项。
- 使用实际读回值拼接全局输出，检查每个有效位置恰好写一次、来源 Tile 正确、全部结果与 Golden 一致。
- 局部测试检查未选中的全局位置未写；整层测试检查全部空间尾部为零且不越界拼接。
- 连续启动、权重组变化、缓存覆盖、装载/完成等待超时及全局 watchdog。

新增 **Design Sources**：

```text

```

新增 **Simulation Sources**（三个都要加入）：

```text
tb/tb_p6_1x1_c256_common.sv
tb/tb_fpga_system_top_p6_1x1_c256_tile.sv
tb/tb_fpga_system_top_p6_1x1_c256_full_layer.sv
```

公共 TB 文件必须加入 Simulation Sources，但不要选它作为本次 Simulation Top，也不要将任何 TB 加入 Design Sources。现有 Cin128 版本的 package、PE、K Controller、Reader、BRAM 等依赖继续使用。

2. 局部通过后，再设置 `tb_fpga_system_top_p6_1x1_c256_full_layer` 为 Simulation Top，重新启动仿真并 Run All。

本轮只做行为仿真准备，无需切换综合顶层。后续若单独综合此配置，RTL 顶层名称才是 `fpga_system_top_p6_1x1_c256_tile`。
