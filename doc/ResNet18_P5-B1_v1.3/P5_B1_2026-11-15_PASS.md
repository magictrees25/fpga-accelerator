# P5-B1：Weight BRAM 共享优化阶段记录

> 日期：2026-11-15  
> 项目：ResNet-18 FPGA 卷积加速器  
> 分支：`p5-b1-weight-bram-sharing`  
> Git 分支 HEAD：`d39293e9ad38805b30930860486a591efae51168`  
> 器件：Xilinx Artix-7 `xc7a100tcsg324-1`  
> 工具：Vivado 2023.2  
> 时钟约束：100 MHz（10 ns）

## 1. 阶段目标

P5-A 已将 3×3/S1、1×1/S2、3×3/S2 三种卷积模式接入同一套 8×8 PE 阵列和 K/M/N Controller，但原有权重存储仍由两套 Weight Reader 分别承担。

P5-B1 的目标是：**把两套 Weight Reader 合并为一个可根据 K 长度工作的 Shared Weight Reader，减少重复权重 BRAM 实例，同时保持原有 128-bit K-pair 输出接口和计算行为不变。**

本阶段不修改 Activation Reader、Controller 和 PE 阵列。

## 2. RTL 修改与存储结构

### 新增/修改文件

| 文件 | 作用 |
|---|---|
| `rtl/conv_weight_bram_reader_p5_shared.sv` | 新增统一双 Bank Weight Reader |
| `rtl/conv_accelerator_top_p5_multimode.sv` | 删除原两套 Weight Reader 实例，改接 `u_weight_shared` |
| `tb/tb_p5_multimode_6runs.sv` | 将权重 RAM 请求检查改为统一 Reader 层级 |
| `rtl/fpga_system_top_p5_multimode.sv` | 多模式系统顶层，封装计算核心和 Output BRAM |

### Shared Weight Reader 结构

- 两个 64-bit Bank，每个 Bank 深度 288；
- Bank 0 保存偶数 K 元素：K0、K2、K4……；
- Bank 1 保存奇数 K 元素：K1、K3、K5……；
- 写入 Bank 内地址采用 `wr_addr >> 1`，由 K 地址奇偶位选择 Bank；
- 每次 pair request 读取两个连续 K 元素，输出打包为原接口 `wgt_pair_packed[127:0]`；
- 最大支持 K=576；1×1/S2 模式使用 K=64，3×3 两种模式使用 K=576。

模式对应关系：

| 模式 | 卷积配置 | K 长度 |
|---:|---|---:|
| 0 | 3×3/S1/P1 | 576 |
| 1 | 1×1/S2/P0 | 64 |
| 2 | 3×3/S2/P1 | 576 |

## 3. 功能仿真验收

仿真顶层：`tb_p5_multimode_6runs`。

测试按 3×3/S1 → 1×1/S2 → 3×3/S2 的顺序运行两轮。六次运行之间不复位；每轮在空闲状态重新加载对应模式的数据和权重。输出与独立 Golden Model 比较。

| Run | 模式 | INT32 输出 | K-pair | Compute cycles |
|---:|---|---:|---:|---:|
| 0 | 3×3/S1 | 512/512 | 18,432 | 19,520 |
| 1 | 1×1/S2 | 128/128 | 512 | 784 |
| 2 | 3×3/S2 | 128/128 | 4,608 | 4,880 |
| 3 | 3×3/S1 | 512/512 | 18,432 | 19,520 |
| 4 | 1×1/S2 | 128/128 | 512 | 784 |
| 5 | 3×3/S2 | 128/128 | 4,608 | 4,880 |
| **合计** | **6 次连续运行** | **1,536/1,536** | **47,104/47,104** | **50,368** |

**结果：六次连续运行全部 PASS，1,536/1,536 个 INT32 输出与 Golden Model 一致。** 测试期间共用一套 PE 阵列，模式切换时不复位。

说明：当前 TB 的部分 console banner/comment 仍写 `P5-A`，属于阶段标签未更新；实际 P5-B1 分支顶层已经连接 `u_weight_shared`。后续应统一修正打印标签和 RTL 头部注释。

## 4. 综合/实现资源结果

以下为 Post-Route PhysOpt 后的资源统计。P5-A 与 P5-B1 使用相同器件与设计时钟目标，按同一实现阶段对比。

| 资源 | P5-A | P5-B1 | 变化 |
|---|---:|---:|---:|
| Slice LUTs | 7,586 | 7,581 | -5 |
| Slice Registers | 4,612 | 4,611 | -1 |
| Block RAM Tile | 13 | **11** | **-2（约 -15.38%）** |
| RAMB36 | 12 | 10 | -2 |
| RAMB18 | 2 | 2 | 不变 |
| DSP | 64 | 64 | 不变 |
| BUFGCTRL | 3 | 5 | +2 |

P5-B1 PhysOpt 后进一步资源拆分：

- LUT as Logic：7,089；
- LUT as Memory：492；
- Slice Registers：4,611；
- RAMB36：10；
- RAMB18：2；
- Block RAM Tile：11；
- DSP：64；
- BUFGCTRL：5。

**核心结果：Weight Reader 共享后 BRAM Tile 从 13 降至 11，减少约 15.38%；DSP 数量保持 64。** 这验证了共享存储实例带来的资源收益。LUT/FF 的变化很小。

### PhysOpt 后最差 Setup 路径

```text
Startpoint:
u_compute/u_ctrl/u_kctrl/k_idx_reg[1]/C

Endpoint:
u_compute/u_act_s1/u_line_buffer/odd_q_reg[0]/D

Data Path Delay : 10.494 ns
Logic Delay     :  4.328 ns
Route Delay     :  6.166 ns
Logic Levels    : 15
Slack           : +0.038 ns
```

关键路径仍是 K Controller 到 P3 Activation Line Buffer，并未经过新增的 Shared Weight Reader。布线延迟约占数据路径 58.8%，说明后续若继续提升频率，应重点分析控制信号扇出、地址/选择逻辑和物理布局。

### 时序结论边界

- 当前 100 MHz 下，报告中已约束的内部 Setup/Hold 检查通过；
- WNS 仅 +38 ps，WHS 仅 +14 ps，裕量较小；
- Timing Summary 仍提示 120 个输入端口没有 Input Delay、37 个输出端口没有 Output Delay；
- 因此不能宣称完整板级 I/O 时序签核通过；
- 目前没有 FPGA 板卡实测、真实 DDR/AXI 传输延迟或功耗数据。

## 7. 阶段结论与下一步

**P5-B1 阶段目标已达成**：统一权重存储结构完成，六次连续多模式功能回归通过，BRAM Tile 减少 2 个，Post-Route PhysOpt 后 100 MHz 已约束内部 Setup/Hold 检查通过。

下一阶段建议进入 **P5-B2 Activation Reader/BRAM 共享评估**。在编码前先明确三种 Activation 路径的共性与差异，尤其是 P3 的 4-Row Line Buffer 与 P4 的直接双 Bank BRAM 读取，不能为追求“一个 Reader”而牺牲缓存时序或边界语义。P5-B1 应保留为稳定对照版本。
