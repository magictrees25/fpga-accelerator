## 1. P5 阶段总结

### 1.1 阶段目标

P5 的目标是在 P3/P4
已分别验证的三种代表性卷积配置基础上，形成统一的多模式卷积计算原型，并逐步消除重复的片上存储资源，最后解决共享存储结构引入的时序问题。

P5 的工作分为四个部分：

1.  **P5-A：三种卷积模式统一集成**，共用一套 8×8 PE 阵列和 K/M/N
    控制核心。
2.  **P5-B1：Weight BRAM 共享**，将原来两套 Weight Reader 合并为一个
    Shared Weight Reader。
3.  **P5-B2：Activation BRAM 共享**，将三种 Activation Reader
    的外部特征图存储统一到一个 Activation BRAM，同时保留 P3 Line
    Buffer。
4.  **P5-B2-5A：K Controller 时序优化**，缩短 K
    地址递增与请求控制组合路径。

### 1.2 当前总体结论

**P5 阶段已完成当前范围内的多模式集成、权重/激活存储共享和 100 MHz
内部时序优化。**

P5-B2-5A 的 Implementation 报告显示：

-   WNS：`+0.514 ns`
-   TNS：`0 ns`
-   Setup failing endpoints：`0`
-   WHS：`+0.052 ns`
-   THS：`0 ns`
-   Hold failing endpoints：`0`
-   BRAM Tile：`8`
-   DSP：`64`

因此，现阶段没有必要为了继续迭代而立即开展 P5-B2-5B。建议将 P5-B2-5A
作为 P5 的稳定对照版本，转入 P6 的计算规模扩展。

**边界说明**：P5 完成不代表 ResNet-18 整网完成。当前仍是由
Host/Testbench 组织 Tile 加载与运行的卷积加速原型，尚未完成完整
ResNet-18 自动调度、板级推理和真实功耗测量。

## 2. P5 统一多模式架构

### 2.1 三种卷积模式

设计顶层为 `fpga_system_top_p5_multimode`，仿真顶层为
`tb_p5_multimode_6runs`。

  --------------------------------------------------------------------------------------------
    `cfg_mode` 卷积配置    单次输入   单次输出            M          N          K Activation
                           Patch      Tile                                        数据路径
  ------------ ----------- ---------- ---------- ---------- ---------- ---------- ------------
             0 3×3/S1/P1   10×10×64   8×8×8              64          8        576 P3 四行 Line
                                                                                  Buffer

             1 1×1/S2/P0   8×8×64     4×4×8              16          8         64 P4 直接读取

             2 3×3/S2/P1   9×9×64     4×4×8              16          8        576 P4 直接读取
  --------------------------------------------------------------------------------------------

三种模式共用：

-   一套 8×8 INT8 PE 阵列（64 个 PE）；
-   一套 K/M/N 计算控制核心；
-   一套 Output BRAM；
-   P5-B1 完成后的一套 Shared Weight Reader；
-   P5-B2 完成后的一套 Shared Activation BRAM。

### 2.2 P5-B1：Weight BRAM 共享

新增 `conv_weight_bram_reader_p5_shared.sv`，将原来两套 Weight Reader
合并为一个双 Bank Reader。

存储组织：

-   Bank 0：保存偶数 K 元素；
-   Bank 1：保存奇数 K 元素；
-   每个 Bank 为 64-bit 宽、深度 288；
-   支持 K=64 和 K=576；
-   保持原有 128-bit K-pair 输出接口。

P5-B1 的主要结果：

-   BRAM Tile：13 → 11，减少 2 个，约 15.38%；
-   DSP：64，保持不变；
-   六次连续多模式仿真：1,536/1,536 INT32 输出通过；
-   Post-Route PhysOpt 后 WNS `+0.038 ns`、TNS `0 ns`、WHS `+0.014 ns`。

### 2.3 P5-B2：Activation BRAM 共享

新增
`conv_activation_bram_shared_p5.sv`，将三种模式使用的外部特征图存储统一为一个
Activation BRAM。

存储组织：

-   两个 8-bit Bank，分别保存偶数和奇数字节地址；
-   `MAX_BYTES=6400`，对应 10×10×64 INT8；
-   一次写入一个 INT8；
-   一次读取一对 INT8；
-   同步读延迟为 1 个时钟周期。

**重要：P3 的四行 Line Buffer 没有删除。** P3 仍使用 Line Buffer
完成滑动窗口数据复用；共享的是其外部特征图 BRAM 访问来源。P4
的两种模式则直接从同一个共享 Activation BRAM 读取。

P5-B2 的主要结果：

-   BRAM Tile：11 → 8，减少 3 个；
-   LUT：7,581 → 7,538；
-   FF：4,611 → 4,612；
-   DSP：64，保持不变；
-   六次连续多模式仿真：1,536/1,536 INT32 输出通过。

### 2.4 P5-B2-5A：K Controller 时序优化

本轮只修改 `rtl/k_tile_controller_p2.sv`，主要变化：

-   使用寄存器 `next_fetch_k` 维护下一次 K-pair 请求地址；
-   使用 `pairs_remaining` 维护剩余 K-pair 数量；
-   避免原先在请求路径中组合计算 `k_idx + 2` 并与 `k_len_saved` 比较；
-   保持原有同步 Reader 一拍响应协议和 FEED/DRAIN 调度节拍。

功能回归仍使用 `tb_p5_multimode_6runs`。用户提供的 XSim
记录显示六次连续运行全部通过，输出 1,536/1,536
正确，原有各模式周期数不变。

## 5. P5 时序结果

### 5.1 各阶段 Routed Implementation WNS

  阶段         Routed Implementation WNS             额外 PhysOpt 结果
  ---------- --------------------------- -----------------------------
  P5-A                         -0.194 ns          PhysOpt 后 +0.005 ns
  P5-B1                        -0.654 ns          PhysOpt 后 +0.038 ns
  P5-B2                        -0.461 ns   未在本表中使用 PhysOpt 数据
  P5-B2-5A                 **+0.514 ns**             当前报告为 Routed

说明：P5-A、P5-B1 曾额外执行 Post-Route PhysOpt；P5-B2-5A 当前报告的
Design State 为 Routed。比较时应区分实现流程，不把 PhysOpt 与普通 Routed
数值混为同一口径。

### 5.2 P5-B2 与 P5-B2-5A 对比

这是本轮时序优化最重要的同阶段对比：

  指标                            P5-B2        P5-B2-5A
  ------------------------- ----------- ---------------
  WNS                         -0.461 ns   **+0.514 ns**
  TNS                         -3.038 ns        **0 ns**
  Setup failing endpoints            14           **0**
  WHS                         +0.046 ns       +0.052 ns
  THS                              0 ns            0 ns
  Hold failing endpoints              0               0
  Data Path Delay             10.483 ns        9.008 ns
  Logic Delay                  4.190 ns        3.048 ns
  Route Delay                  6.293 ns        5.960 ns
  Logic Levels                       14              12

结果：

-   WNS 改善 **0.975 ns**；
-   TNS 收敛到 0；
-   14 个 Setup 违例端点全部消除；
-   Hold 检查通过；
-   最差路径逻辑级数由 14 级降至 12 级。

### 5.3 关键路径变化

P5-B2 原始关键路径：

-   Startpoint：`k_idx_reg[1]`；
-   Endpoint：P3 Line Buffer 的 `even_q_reg[7]/D`；
-   路径经过 K 地址递增、边界比较和请求控制逻辑。

P5-B2-5A 当前关键路径：

-   Startpoint：`pairs_remaining_reg[14]`；
-   Endpoint：Shared Activation BRAM Bank 1 的 `ENBWREN`；
-   Data Path Delay：9.008 ns；
-   Logic Delay：3.048 ns；
-   Route Delay：5.960 ns；
-   Logic Levels：12。

当前最差路径的布线延迟约占 66.16%。这说明 K
地址递增与边界比较不再是最差路径，剩余瓶颈转移到 K Controller、Reader
地址/接受逻辑和 Shared Activation BRAM 使能路径。

### 5.4 时序结论边界

P5-B2-5A Implementation 报告：

-   Design State：Routed；
-   sys_clk 周期：10 ns，即 100 MHz；
-   Setup WNS：+0.514 ns，TNS：0；
-   Hold WHS：+0.052 ns，THS：0；
-   9,838/9,838 条 routable nets fully routed；
-   Routing Errors：0。

但报告仍提示：

-   120 个输入端口没有指定 Input Delay；
-   37 个输出端口没有指定 Output Delay。

因此，准确结论是：**当前 100 MHz 约束下，已约束的内部 Setup/Hold
时序检查通过；尚不能据此宣称完整板级 I/O 时序签核通过。**

当前 GitHub 的 P5-B2-5A Implementation 目录尚未看到独立 DRC 和 Power
报告。DRC/功耗应标为待补充，不应写成已经通过或已经测量。

## 7. P6 阶段目标：更大 Cin/Cout 与 K-Tile 累加

### 7.1 为什么进入 P6

P5 当前主要验证 Cin=64、单次 N=8 的计算 Tile：

-   3×3 卷积：K=3×3×64=576；
-   1×1 卷积：K=64；
-   Shared Weight Reader 的最大 K 为 576；
-   Shared Activation BRAM 容量为 6,400 bytes，对应 10×10×64；
-   P3/P4 Activation Reader 的地址映射围绕 Cin=64 构建；
-   `gemm_mn_controller_mem_p2` 当前检查条件为 M≤64、N=8、K 为正偶数。

ResNet-18 后续阶段需要支持：

  代表层                      输入通道 Cin   输出通道 Cout 卷积       完整 K
  ------------------------- -------------- --------------- -------- --------
  `layer3.0.downsample.0`              128             256 1×1/S2        128
  `layer3.0.conv1`                     128             256 3×3/S2      1,152
  `layer3.0.conv2`                     256             256 3×3/S1      2,304
  `layer4.0.conv1`                     256             512 3×3/S2      2,304
  `layer4.0.conv2`                     512             512 3×3/S1      4,608

因此，P6 的重点不是简单地把 K 计数器位宽加大，而是建立可验证的
**输入通道分块（C-Tile）、跨 K-Tile INT32 部分和累加，以及更多输出通道
N-Tile 调度**。

### 7.2 推荐方案：保持 64 输入通道一个 C-Tile

建议 P6 初期继续复用 P5 的 8×8 PE 和现有双 Bank 存储组织，不立即把
Activation/Weight BRAM 扩展到完整 Cin。

采用：

-   `C_TILE=64`：每次向当前硬件加载 64 个输入通道；
-   `N_TILE=8`：每次计算 8 个输出通道，与 8 列 PE 对应；
-   `M_TILE=16`：优先用于 4×4 输出空间 Tile；
-   `M_TILE=64`：用于 8×8 输出空间 Tile。

对应 K-Tile：

  卷积类型     单个 C-Tile 对应 K-Tile
  ---------- -------------------------
  1×1                      1×1×64 = 64
  3×3                     3×3×64 = 576

输入通道分块数量：

    Cin   C-Tile 数
  ----- -----------
     64           1
    128           2
    256           4
    512           8

输出通道分块数量：

    Cout   N-Tile 数
  ------ -----------
     128          16
     256          32
     512          64

这样可以在不改变 8×8 PE 规模的前提下，先复用现有 64 通道数据通路和
K=64/576 的 Reader。Host/PS 每次装载一个 C-Tile 的激活数据，以及一个
N-Tile 对应的权重数据。

### 7.3 P6 最关键的 RTL 问题：跨 C-Tile 部分和

当前 `mac_unit.clear_acc` 不仅清零 INT32
累加器，也会清除输入寄存器和乘法寄存器；`systolic_array_p2` 还使用
`clear_acc` 清除权重 skew 和有效流水状态。

因此，不能简单地在第二个 C-Tile 开始时取消所有清零信号，也不能每个
C-Tile 都执行原来的 `clear_acc`。

P6 需要把两种控制职责分离：

1.  **Accumulator Clear**：只在第一个 C-Tile 开始时清零 PE 的 INT32
    累加器；
2.  **Pipeline Clear**：每个 C-Tile 开始时清理 MAC
    输入/乘法流水寄存器、权重 skew 和有效流水状态，但保留 INT32 累加器。

建议新增独立的 `clear_pipe`（名称可在 RTL 接口设计时最终确定），并设计
C-Tile 间的装载握手：

``` text
开始一个 M/N 输出 Tile
        |
        v
C-Tile 0：加载 64 通道数据
        |
        v
清空 Accumulator + Pipeline
        |
        v
计算 K-Tile，得到部分和
        |
        v
等待下一 C-Tile 装载
        |
        v
C-Tile 1：加载下一组 64 通道数据
        |
        v
只清 Pipeline，保留 Accumulator
        |
        v
继续计算并累加
        |
        v
最后一个 C-Tile 完成
        |
        v
写回最终 INT32 输出
```

**建议在所有 C-Tile
完成后再写回最终输出**，避免把中间部分和误当作最终结果。需要明确 Host
preload、计算暂停、Pipeline Clear、Accumulator 保留和最终 writeback
的时序关系。

## 8. P6 开发里程碑与验收标准

### P6-A：跨 K-Tile 累加微型验证

目标：先不做整层，验证 PE 能否跨两个 K-Tile 保留并累加 INT32 部分和。

建议测试：

-   M=1 或 M=16；
-   N=8；
-   K_total=128；
-   分成两个 K-Tile，每个 K-Tile=64；
-   第一个 K-Tile 清零 Accumulator；
-   第二个 K-Tile 只清 Pipeline，保留 Accumulator；
-   两个 K-Tile 之间不复位；
-   最终结果逐项匹配独立 Golden Model。

验收标准：

-   两个 K-Tile 的输入/权重数据均正确；
-   第二个 K-Tile 不清空第一个 K-Tile 的累加结果；
-   不出现旧 Pipeline 数据重复累加或漏累加；
-   最终 INT32 输出全部匹配 Golden Model；
-   只在最后一个 K-Tile 后执行最终 writeback。

### P6-B：扩展 `layer3.0.downsample.0`

优先选择 1×1/S2，因为它可以先验证 Cin/Cout 扩展和跨 C-Tile
累加，不必同时引入新的 3×3 地址映射问题。

网络参数：

-   输入：28×28×128；
-   卷积：1×1/S2/P0；
-   输出：14×14×256；
-   完整 K=128；
-   C-Tile：2 个，每个 K=64；
-   N-Tile：32 个，每个 N=8；
-   空间 Tile：4×4 输出，共 4×4=16 个空间 Tile；
-   每个空间 Tile 的 M=16。

按上述 Tile 组织，计划覆盖 16 个空间 Tile × 32 个 N-Tile × 2 个
C-Tile，共 **1,024 个计算分块任务**。14×14 输出边界处需要明确尾 Tile
的有效输出掩码，不能把填充位置写入最终全局输出。

全层验收：

-   14×14×256 = **50,176 个 INT32 输出**；
-   全部输出与独立 Golden Model 逐项一致；
-   两个 C-Tile 之间无复位，部分和正确；
-   32 个 N-Tile 的权重加载和输出通道拼接正确；
-   右侧、底部尾 Tile 的无效输出不写入全局结果。

### P6-C：扩展 `layer3.0.conv1`

网络参数：

-   输入：28×28×128；
-   卷积：3×3/S2/P1；
-   输出：14×14×256；
-   完整 K=1,152；
-   按 Cin=64 分块：2 个 C-Tile，每个 K-Tile=576；
-   N-Tile：32；
-   空间 Tile：16。

本阶段重点验证：

-   每个 C-Tile 内 `(ky,kx,ci_local)` 到 K 地址的映射；
-   不同 C-Tile 对应全局输入通道范围的映射；
-   Padding 与边界 Tile；
-   跨两个 K-Tile 的 INT32 部分和；
-   50,176 个输出的全层 Golden 对比。

### P6-D：继续扩展到更大 Cin

在 P6-B/P6-C 通过后，再逐步扩展：

  目标层               完整 K   C-Tile 数
  ------------------ -------- -----------
  `layer3.0.conv2`      2,304           4
  `layer4.0.conv1`      2,304           4
  `layer4.0.conv2`      4,608           8

每增加一种配置，都先完成地址/数据映射检查、K-Tile
部分和验证、边界测试，再进行全层 Golden 回归。不要直接从 K=576 跳到
K=4608 后一次性调试。

## 9. P6 分支与代码管理建议

P5-B2-5A 应保持稳定，不在其分支上直接开发 P6。

建议从 `p5-b2-5-timing-opt` 创建新分支：

``` bash
git switch p5-b2-5-timing-opt
git pull --ff-only origin p5-b2-5-timing-opt

git switch -c p6-ktiling-accum
git push -u origin p6-ktiling-accum
```

P6 初期建议先设计/验证以下模块职责，再决定是扩展原模块还是新增 P6
专用模块：

  --------------------------------------------------------------------------
  模块职责                            P6 需要解决的问题
  ----------------------------------- --------------------------------------
  MAC / PE                            Pipeline Clear 与 Accumulator Clear
                                      分离

  Systolic Array                      C-Tile 边界清 Pipeline、保留 PE 累加值

  K-Tile Sequencer                    管理 C-Tile 次数、K-Tile 启动和完成

  M/N Controller                      在同一 M/N 输出 Tile 内完成多个 C-Tile
                                      后再写回

  Host/Preload 接口                   装载下一组 64
                                      通道激活与对应权重，并与计算控制握手

  Testbench                           验证两段/多段 K-Tile、尾 Tile、Golden
                                      和无复位切换
  --------------------------------------------------------------------------

推荐开发顺序：

1.  先完成 P6-A 的独立 Testbench；
2.  再设计跨 C-Tile 的控制接口；
3.  通过 P6-B 的 1×1/S2 完整层验证；
4.  再扩展 P6-C 的 3×3/S2；
5.  每个里程碑均重新执行功能回归、Synthesis 和 Implementation。

## 11. 最终结论

P5 已完成统一多模式卷积计算、Weight BRAM 共享、Activation BRAM 共享和 K
Controller 时序优化。当前 P5-B2-5A 在 100 MHz 下已约束内部 Setup/Hold
时序通过，BRAM Tile 从 P5-A 的 13 个减少到 8 个，DSP 保持 64
个，六次连续多模式回归输出 1,536/1,536 正确。

下一阶段 P6 应聚焦 **Cin/Cout 扩展和跨 K-Tile 部分和累加**，优先以
`layer3.0.downsample.0`（1×1/S2，Cin=128、Cout=256）作为第一个完整层目标，再扩展到
`layer3.0.conv1`（3×3/S2，K=1,152）。

P5-B2-5A 保留为稳定对照版本；P6 在独立分支中开发，避免破坏已完成的 P5
结果。
